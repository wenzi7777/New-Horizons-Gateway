# studio-v2.11.1

**Windows ファイアウォールがデバイスのデータをブロックしていると、接続済みなのに NH Studio でオフラインのままになり、「引き継ぐ」を押すまで直らなかった問題を修正しました。**

## 原因

Windows ファイアウォールの規則はネットワークの種類（プライベート／パブリック）ごとに設定されます。NH Studio の初回起動時に一方だけを許可していると、もう一方のネットワークではデバイスから届くデータ（UDP 13250 のハートビートとストリーム）がブロックされます。Studio が自分で送る FindMe は通るため、デバイスはリースを更新しているのにオフラインと表示されていました。

## 修正

- NH Studio は見つけたばかりのデバイスにデータ用ポートから 1 バイトを先に送り、ファイアウォールがデバイスからの応答を通すようにします。サービス中のデバイスには 20 秒ごとに送り直し、許可が切れないようにします。デバイスはこの 1 バイトを無視します（すべてのファームウェア）。headless も同様です。
- デバイスがこの Studio とリースを更新し続けているのに 15 秒間データが届かない場合、デバイス一覧とデバイス画面に「このコンピュータのファイアウォールがブロックしている可能性」と Windows での設定方法を表示します。headless は警告をログに書きます。
- Windows インストーラーがファイアウォール規則を追加します。すべての種類のネットワークで NH Studio が UDP 13250 と 22346 を受信できるようにし、Windows が以前作成した規則を削除します。規則がないときだけ管理者の確認を 1 回求め、以後の更新では求めません。アンインストール時に削除します。

## 手動での修正（旧バージョン、または更新前）

管理者として実行した PowerShell で `Set-NetFirewallRule -DisplayName "NH Studio" -Profile Any` を実行してください。

## その他

- NH Pocket は変更なし（2.11.0）。ファームウェアと Desktop の更新は不要です。
