# New Horizons Gateway v0.5.3

## Changes

### Recognize NHO/Arduino/1 protocol v4 packets (real epoch timestamp)

- Devices on New Horizons OS firmware v0.11.3+ send a wider packet header (24
  bytes vs. 20) carrying a real NTP-synced epoch timestamp instead of
  `millis()`-since-boot.
- `is_arduino_stream_packet` and `is_arduino_heartbeat_packet` in
  `arduino_protocol.py` hardcoded protocol version 3 and a 20-byte header for
  their own routing/validation — the Gateway is not protocol-blind here, so
  without this update it would silently fail to recognize any v4 packet as a
  valid Arduino stream/heartbeat packet.
- Both functions now branch on packet version to pick the matching header
  length/struct, so v3 (legacy, uptime-based) and v4 (epoch-based) devices are
  both recognized correctly.
- Companion release to New-Horizons-OS v0.11.3 and a matching
  New-Horizons-Desktop backend update — all three need to be running this
  version or newer for v4 devices to work end-to-end through this Gateway.

## Verification

- `python3 -m unittest tests.test_gateway_bootloader -v`
- Standalone smoke test of `is_arduino_stream_packet`/`is_arduino_heartbeat_packet`
  against hand-built v3, v4-synced, v4-unsynced, and truncated packets — all
  classify correctly, no crashes on malformed input.
