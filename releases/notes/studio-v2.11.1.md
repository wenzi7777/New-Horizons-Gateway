# studio-v2.11.1

**修正 Windows 防火牆擋住設備資料時，設備明明已連上卻一直顯示離線、要按「接管」才恢復的問題。**

## 原因

Windows 防火牆的規則是依網路類別（私人／公用）設定的。NH Studio 第一次啟動時，若只允許了其中一種網路，換到另一種網路後，設備主動送來的資料（UDP 13250 的 heartbeat 與串流）就會被擋，但 Studio 自己送出的 FindMe 仍然正常，所以設備在續約、卻一直顯示離線。

## 修正

- NH Studio 先從資料埠送一個位元組給剛找到的設備，防火牆就會放行設備的回覆；服務中的設備每 20 秒再送一次，避免放行逾期。設備會直接忽略這個位元組（所有韌體版本）。headless 也一樣。
- 設備持續向這台 Studio 續約、但 15 秒都收不到它的資料時，設備列表與設備頁會提示「可能被本機防火牆攔截」，並說明 Windows 的設定方法；headless 會寫一行警告 log。
- Windows 安裝程式新增防火牆規則：允許 NH Studio 在所有網路類別接收 UDP 13250 與 22346，並移除 Windows 先前為它建立的規則。只在規則不存在時跳一次系統管理員確認，之後更新不會再問；解除安裝時移除。

## 手動修正（舊版或不想等更新時）

以系統管理員身分開啟 PowerShell，執行 `Set-NetFirewallRule -DisplayName "NH Studio" -Profile Any`。

## 其他

- NH Pocket 不變（2.11.0）。韌體與 Desktop 不需更新。
