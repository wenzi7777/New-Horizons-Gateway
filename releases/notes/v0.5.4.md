# New Horizons Gateway v0.5.4

## Changes

### Prune stale device entries instead of keeping them forever

- `GatewayState.devices` never removed an entry once created -- a device
  that migrated to a different Gateway/Hub (or left for good) kept getting
  re-asserted into every ~5s `gateway_status` heartbeat forever with a
  correctly-negative but still non-owning `connected: false` claim. On the
  Desktop backend side, this repeatedly tripped a too-permissive merge
  condition (fixed separately in New-Horizons-Desktop v0.5.4) and was one of
  the two causes of the FindMe/device page's shown gateway/hub flickering
  between the true owner and a long-departed Gateway.
- A device now gets pruned entirely from `self.devices` (not just flagged
  `connected: false`) once neither its control traffic nor its FindMe
  requests have been seen for `prune_after_sec` (default 300s, floored at
  `control_stale_sec`). A device only ever seen via a denied/rejected FindMe
  request is still eligible for pruning -- it never sets
  `last_seen_monotonic`, so pruning uses whichever of that and
  `last_findme_monotonic` is newer.
- This also fixes unbounded growth of `self.devices` on a long-running
  Gateway that's seen many devices come and go.

## Also in this release

- Companion fix to New-Horizons-Desktop v0.5.4 (the merge condition on the
  backend side is the one that actually stops the display flicker; this
  release is complementary hygiene cleanup on the Gateway's own roster).
